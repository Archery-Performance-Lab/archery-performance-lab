# Security Policy

## Overview

The Archery Performance Lab (APL) project is committed to maintaining a secure, reliable and trustworthy open-source environment.

Although the current release is focused on documentation and repository foundations, security is considered a fundamental aspect of the project's long-term development.

---

# Supported Versions

At this stage of the project, only the latest published version is supported.

| Version | Supported |
|---------|-----------|
| 0.1.x | ✅ Yes |
| Earlier versions | ❌ No |

---

# Reporting a Security Vulnerability

If you believe you have discovered a security vulnerability in APL, please do **not** disclose it publicly before it has been reviewed.

Instead, report the issue privately by contacting the project maintainers.

When reporting a vulnerability, please include:

- A clear description of the issue.
- Steps required to reproduce the problem.
- Potential impact.
- Suggested mitigation (if available).
- Any relevant logs or supporting information.

---

# Response Process

Every reported vulnerability will be:

1. Acknowledged.
2. Reviewed.
3. Validated.
4. Prioritized.
5. Corrected when appropriate.
6. Documented in the project changelog if applicable.

The project maintainers will make reasonable efforts to respond promptly.

---

# Responsible Disclosure

We ask all contributors and researchers to practice responsible disclosure.

Please allow sufficient time for investigation and remediation before publicly discussing security-related issues.

---

# Security Principles

APL follows these general principles:

- Least complexity whenever possible.
- Transparency in design.
- Documented architecture.
- Traceable changes.
- Reproducible development process.
- Open review of non-sensitive security improvements.

---

# Scope

This policy applies to:

- Source code.
- Repository configuration.
- Documentation.
- Future APIs.
- Future web services.
- Future desktop and mobile applications.

---

# Third-Party Dependencies

When software dependencies are introduced, the project will:

- Prefer actively maintained libraries.
- Keep dependencies updated.
- Remove unused packages.
- Review dependency security periodically.

---

# Contact

Security-related communications should be directed to the project maintainers using the official contact information published by the project.

---

Security is a shared responsibility.

Every contributor helps improve the reliability and trustworthiness of Archery Performance Lab.
