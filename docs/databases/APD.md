# 1. Purpose

The APL Performance Database (APD) is the official performance domain of Archery Performance Lab.

APD stores every performance generated by an athlete during training sessions, competitions and technical assessments.

The database is designed to preserve both raw measurements and derived analytical data while ensuring complete historical traceability.

---

# 2. Scope

APD manages:

- Training Sessions
- Competitions
- Shooting Ends
- Individual Shots
- Scores
- Performance Snapshots
- Raw Data
- Derived Data
- Analytics
- Historical Performance

---

# 3. Architecture

```text
APD
│
├── TrainingSessions
├── Competitions
├── Ends
├── Shots
├── Scores
├── Snapshots
├── RawData
├── DerivedData
├── Analytics
└── History
```

Each entity owns its own data model.

Relationships are managed exclusively by ACE.

---

# 4. Design Principles

APD follows the APL architectural principles.

- Scientific integrity
- Historical preservation
- Immutable raw measurements
- Reproducible analysis
- Modular
- Versioned
- Technology independent

---

# 5. Training Session Entity

Stores:

- UUID
- Session ID
- Athlete Reference
- Equipment Setup Reference
- Arrow Setup Reference
- Environment Reference
- Date
- Time
- Location
- Session Type
- Training Objective
- Notes

A Training Session is the parent entity for Ends and Shots.

---

# 6. Competition Entity

Stores:

- UUID
- Competition ID
- Event Name
- Federation
- Competition Type
- Division
- Category
- Distance
- Round
- Qualification Result
- Elimination Result
- Final Ranking
- External Reference (optional)

Competition performances follow the same structure as Training Sessions.

---

# 7. End Entity

Stores:

- UUID
- End Number
- Number of Arrows
- Total Score
- Duration
- Sequence
- Notes

An End contains one or more Shots.

---

# 8. Shot Entity

The Shot is the smallest measurable performance unit.

Stores:

- UUID
- Shot Number
- Arrow Number
- Score
- Timestamp
- Time From End Start
- Target Coordinates (optional)
- Video Reference (optional)
- Notes

Future versions may include:

- Release Quality
- Execution Rating
- Biomechanical Metrics

---

# 9. Score Entity

Stores scoring information independently from the Shot.

Examples:

- Decimal Score
- Integer Score
- X Count
- Gold Count
- Miss
- Penalty

Different scoring systems may coexist.

---

# 10. Performance Snapshot

A Performance Snapshot represents the complete technical context of a performance.

Each Snapshot references:

- Athlete
- Equipment Setup
- Arrow Setup
- Environment
- Training Session or Competition
- Analytics

Snapshots allow complete reconstruction of historical performances.

---

# 11. Raw Data

Raw Data represents directly observed or measured information.

Examples:

- Score
- Timestamp
- Target Position
- Temperature
- Wind
- Humidity
- Equipment Used

Raw Data is immutable.

It shall never be modified after validation.

---

# 12. Derived Data

Derived Data is generated from Raw Data.

Examples:

- Average Score
- Group Diameter
- Vertical Dispersion
- Horizontal Dispersion
- Mean Shooting Time
- Consistency Index
- FOC Calculations
- Performance KPIs

Derived Data may be recalculated when analytical models evolve.

---

# 13. Analytics

Stores analytical results generated by AIE.

Examples:

- Trends
- Correlations
- Performance Indicators
- Statistical Models
- Predictive Analysis

Analytics never modifies Raw Data.

---

# 14. Historical Preservation

APD preserves the complete performance history.

No historical performance shall ever be deleted.

Corrections generate new revisions while preserving previous versions.

---

# 15. Versioning

Every performance entity supports versioning.

Historical revisions remain permanently available.

Derived Data may evolve without affecting Raw Data.

---

# 16. Validation

Before storage, ACE validates:

- Athlete Reference
- Equipment Setup
- Arrow Setup
- Environment
- Session Integrity
- Score Integrity
- Chronological Consistency

Invalid records shall be rejected.
