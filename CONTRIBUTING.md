# Contributing to Archery Performance Lab (APL)

Thank you for your interest in contributing to Archery Performance Lab.

APL is an open research project that welcomes contributions from athletes, coaches, researchers, engineers, software developers and sports scientists.

Our objective is to build a transparent, reproducible and scientifically rigorous platform for archery performance analysis.

---

# Before Contributing

Please read the following documents before contributing:

- README.md
- ROADMAP.md
- CHANGELOG.md
- CODE_OF_CONDUCT.md

---

# Guiding Principles

Every contribution should follow these principles:

- Scientific rigor.
- Transparency.
- Reproducibility.
- Respect for documented methodologies.
- Clear documentation.
- Long-term maintainability.

---

# Types of Contributions

Contributions may include:

- Documentation improvements.
- Bug reports.
- Bug fixes.
- New features.
- Data models.
- Research datasets.
- Mathematical models.
- Performance analysis methods.
- Software development.
- Technical reviews.

---

# Reporting Issues

When opening an Issue, please include:

- Clear description.
- Expected behaviour.
- Actual behaviour.
- Steps to reproduce.
- Environment details (if applicable).

Whenever possible, provide supporting documentation.

---

# Pull Requests

Before submitting a Pull Request:

- Keep changes focused on a single topic.
- Update documentation when necessary.
- Update CHANGELOG if appropriate.
- Ensure consistency with project philosophy.

Every Pull Request will be reviewed before merging.

---

# Commit Messages

APL follows a simple commit convention.

Examples:

```text
docs: update README

docs: add ROADMAP

feat(M04): add FOC calculation

feat(video): add timing analysis

fix(data): correct validation logic

refactor(core): simplify data model
```

Commit messages should be concise and descriptive.

---

# Coding Standards

When contributing code:

- Write readable code.
- Prefer simplicity.
- Document public interfaces.
- Avoid unnecessary complexity.
- Preserve backward compatibility whenever possible.

---

# Documentation Standards

Documentation is considered part of the project.

All documentation should be:

- Clear.
- Concise.
- Consistent.
- Technically accurate.
- Written in English.

---

# Scientific Contributions

Scientific proposals should:

- Describe assumptions.
- Explain methodology.
- Reference equations when appropriate.
- Distinguish measured, calculated and estimated values.
- Preserve reproducibility.

---

# Review Process

Every contribution may be reviewed for:

- Technical quality.
- Scientific consistency.
- Documentation quality.
- Repository coherence.

Acceptance is based on project quality rather than contribution size.

---

# Questions

If you are unsure about a contribution, open an Issue before starting development.

Early discussion often leads to better solutions.

---

Thank you for helping improve Archery Performance Lab.
